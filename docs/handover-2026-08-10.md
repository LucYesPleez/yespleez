### The rules that came out of it

⭐⭐ **An enquiry is THIS ACT asking THIS VENUE about THIS DATE.**
`UNIQUE (venue_profile_id, applicant_profile_id, date_requested)`. Owner's
reason: *"if I have multiple acts I should be able to apply on the hope they
choose one of them."* ⛔ The same act twice is still refused — that is what makes
"You have already enquired about…" possible.

⭐⭐ **An Ask Category describes the requested SUPPLY, never the identity of the
supplier.** `DJ → music`, `comedian → performance_artist`. ⚠ `artist → music` is
only an implementation shortcut that holds because roles currently live inside
profile types — the resolver keys on the ROLE so it survives one person being a
DJ, a comedian and a facilitator at once.

⭐ **Every unknown BLOCKS** (the enquiry gate). Requirements unread, verdict in
flight, or a verdict describing the act they just switched away from — all
refuse. `null` means unread; `[]` means "asks nothing"; the DB's NULL is
collapsed to `[]` at the fetch boundary so in memory null can only mean unread.

⭐ **Gate first, confirmation second.** The P6 requirements check runs before the
P8 dialog can open, so "don't ask me again" can never dismiss a rule.

## 5. ⚠⚠ The traps that cost real time today

**A live login screen proves a deployment EXISTS, not that it is YOURS.** Preview
`3146faf6` rendered perfectly and was the PREVIOUS commit. ⭐ **Read the bundle
before looking at pixels** — fetch the asset, count the expected strings, and
search for the OLD code's ABSENCE. Seconds, no sign-in.

**Take the per-deployment hostname Cloudflare shows.** The branch-alias form
(`v2-react.yespleez.pages.dev`) 404s even when the build succeeded.

**Pick discriminators that are actually absent from production.** `required_items`
and `Performance` both already existed and would have "passed" against the old
bundle. Baseline every candidate first.

**The propagation split is the norm.** Loop until ~8 cache-busted fetches agree;
it fired again on the final promotion.

**`notifications.id` is a UUID — ordering by it is NOT chronological.** An
id-ordered check reported a phantom missing notification. Order by `created_at`.

**Source-level contract tests prove wiring, not compilation.** A `{/* */}` comment
between JSX attributes passed 923 tests and failed the build. The build is the
only compile check in the sweep.

**⭐⭐ READ THE DATABASE, NOT THE SCREEN.** Three of today's bugs were invisible in
the UI and obvious in the rows: the duplicate enquiry that faked success, the
outgoing surface that never existed, and `acceptInvite` losing attribution.

## 6. The release ritual, as practised

    commit on v2-react → push → per-deployment preview URL
      → READ THE BUNDLE → browser check → --ff-only into main → push
      → verify the production bundle + 8 edge fetches agree

⚠ **Migrations go FIRST**, before the code that reads them — they are additive,
so the database leading is the safe direction. P9 was the one exception worth
noting: it could not be applied before `0758227` was live, because that commit
removed the last thing that could write a NULL profile id.
