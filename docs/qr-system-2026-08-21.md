# QR system (QR1) — built 2026-08-21

Scene now has a QR **destination generator**, not an Event QR feature. This
document is the handover: what exists, the rules that must not be broken, what
is verified, and what is still open.

---

## 1 · The one principle

> **YesPleez owns the destination. The graphic is an export of it.**

A QR is a printed object. Once it is on a poster, a bathroom door or a venue's
front window it can never be corrected, so:

- the encoded string is `https://yespleez.com/#/q/{type}/{id}` — an entity id,
  which is permanent
- resolution happens **when the code is scanned**, so an event whose venue,
  lineup, times or artwork changed still resolves
- **nothing about a scan touches the database.** `qr_codes` is the user's saved
  library. Drop the table and every printed code keeps working.

**Adding a destination type** is one entry in `DESTINATIONS` plus one selector
case. Stage, Programme, Ticket and Check-in are expected to arrive that way.
Nothing in the renderer, the PDF or the generator changes.

**It is not in `packages/`.** Festival will want it, and that is when it gets
extracted — per the monorepo rule, a package is extracted when the dependency
graph reveals a domain, not invented ahead of one consumer.

## 3 · The destinations

| Type | Opens | Offered to |
|---|---|---|
| `event` | `/event/{id}` | anyone with an event they manage |
| `set-times` | `/event/{id}/set-times` | same |
| `venue` | `/profile/{id}` | venue profiles you own |
| `whats-on` | `/profile/{id}?focus=whats-on` | venue **or** host profiles you own |
| `artist` | `/profile/{id}` | your performer profiles, **or** acts booked onto your events |
| `festival` | `/profile/{id}` | **nobody — `available: false`** |

Festival is architected, not built: the type is real, its address is already
decided, and no menu offers it. When the Portal's model is ready the flag flips
and nothing else in the QR system moves.

### Event and Set Times are two objects, deliberately

The event page answers *what is this*; set times answers *what is happening, and
when*. One goes on the poster three weeks out, the other is taped by the door on
the night. `/event/:id/set-times` is a real public route rendering the existing
`SchedulePortrait` — same resolved schedule, same interactive `SlotCard`s, no
duplicated logic. The organiser's `showTimesPublicly` gate is honoured, and the
withheld state **says so** rather than showing a blank page.

### What's On is the permanent one

Print it once and leave it up. Identity is in the **path**; `?focus=whats-on` is
a scroll hint, so a scanner that strips query strings still lands on the right
venue.

## 4 · The rules that must not be broken

- **⛔ `PUBLIC_ORIGIN` is a constant, never `window.location.origin`.** A poster
  generated from a dev server would otherwise encode `http://localhost:5173`,
  and the preview would look perfect. There is a test that fails if
  `window.location` appears anywhere in `qrDestinations.js`.
- **⛔ Never rename a destination key.** It is a path segment in addresses that
  are already printed. Only ever add.
- **⛔ Never make a `/q/` route ACCOUNT-class.** A sign-in wall behind a QR is
  the participation wall O1 removed, by another door.
- **⛔ The code is never inverted and never loses its quiet zone.** Both are out
  of spec and both fail on real cameras, and both look fine on screen.
- **⛔ Retire, never delete.** Deleting a saved row does not un-print the flyers.
- **⛔ A dead destination is shown, not hidden.** The owner may have it printed.

## 5 · Why the encoder is hand-rolled, and why that is safe

`ShareSheet.jsx` reserved the QR slot rather than building it, and gave the
reason: *"a hand-rolled QR encoder is exactly the kind of code that is subtly
wrong in ways that are hard to see."* That objection is correct and it is
answered structurally, not by assertion.

`lib/qr/qrEncode.test.js` **is a decoder.** It rebuilds the function-module map
from geometry, reads the mask and EC level off the symbol's own format bits,
unmasks, de-interleaves the blocks and parses the byte segment. A symbol passes
only when a reader that shares no code path with the writer returns the original
string. 34 symbols across v1–v40 and all four levels, including UTF-8 and emoji.

**If that file is ever "simplified" into golden-matrix assertions, the encoder
loses the only check that means anything.**

Known gap: the matrices under test have no errors in them, so Reed-Solomon
parity is computed but never exercised. Wrong parity would not fail the suite —
it would fail on a scuffed poster. That is why the acceptance step below is
still *scan a print*.

## 6 · The poster

⭐⭐ **One template, every destination** (owner, 2026-08-21, from a supplied
poster): black ground edge to edge, enormous condensed cream caps with a printed
grain, a widely tracked tan sub-line, a white rounded plate holding the code, and
`- SCAN OR GO TO YESPLEEZ.COM -` at the foot. **A3 by default**; A4 and A5 are
the same poster at another size, and a crop of the PNG serves for socials.

⭐⭐ **ONE LAYOUT, THREE OUTPUTS.** `qrPosterLayout.js` decides where every shape
goes and paints nothing; `qrPdf.js` draws that list as PDF operators and
`qrPosterCanvas.js` draws the identical list to a canvas for the PNG and the
on-screen proof. ⛔ There is no second implementation of the design to drift.
Before this, the preview was a CSS lookalike and it had already drifted: it sized
the headline by counting characters instead of measuring the face, so the proof
showed type a fifth smaller than it printed.

**The headline is compressed to 73%**, which is measured off the reference, not
chosen. Bebas at its natural width tops out at a cap height of about 20% of the
page width once a line fills the margins; the reference reaches 27%, and the
difference is exactly this squeeze — narrower glyphs let the same line width
carry much taller caps.

⭐⭐ **The grain is vector.** Text rendering mode 7 turns the glyph outlines into
a clipping path and the flecks are ordinary rectangles painted inside it, so the
letters stay sharp at any size. The scatter is a deterministic hash walk seeded
from the text: ⛔ never `Math.random`, or re-downloading a poster you already
printed would come back with a different texture from the one on the wall.

⚠ **The letters are painted BEFORE anything is clipped, and that is a safety
property.** A reader that ignores text clipping still renders a correct headline
with a few stray flecks. The obvious alternative — clip first, then flood the box
with cream — paints a solid slab over the poster on that same reader.

⚠⚠ **Accents rise above cap height and the leading is tighter than they are.**
Measured off the face: plain caps 0.703em, É/Á/Ñ 0.875, Å 0.922, and Ç drops
0.156 *below* the baseline — against 0.80em of leading. On `SOLSTICE / SOIRÉE`
the acute poked into the line above and read as a stray slash through the word.
It looked like a rendering bug and it was ordinary typography. The leading is now
derived from what the lines contain: a plain title keeps the tight 0.80em, an
accented one opens to 0.875em, and that is all. ⛔ It matters because whether the
accent lands in a gap between letters or straight through one is pure luck of the
title.

**The face is Bebas Neue, embedded.** It is the app's own display face and it is
what makes a YesPleez poster recognisable across a room. The cheap alternative
was Helvetica-Bold squeezed with the `Tz` operator, which thins the vertical
strokes while the horizontals stay fat — obvious at 160pt, and it reads as a
mistake. So `qrFont.js` parses the TrueType file and writes a proper
`/FontFile2` with widths from `hmtx` and a descriptor from `head` / `hhea` /
`OS/2`. Licence: SIL OFL 1.1, `fsType` 0 (checked, not assumed), and the licence
ships beside the file at `public/fonts/BebasNeue-OFL.txt`.

⚠ **If the font asset will not load, the export still produces a poster**, in
squeezed Helvetica. ⛔ It does not fail, and it does not pretend: `usedFont`
records which happened, and a test pins both paths.

**The headline is balanced, not wrapped.** Greedy wrapping fills each line to the
margin and dumps the remainder on the last one, so a title breaks as
`WHAT'S ON IN` / `BELLO?` and the poster looks broken. The layout instead
partitions the words so the widest line is as narrow as possible, then sizes to
that — which is why it matches the reference (`WHAT'S ON` / `IN BELLO?`) and why
the type can be so large: evening the lines out makes every line bigger.
⛔ A title is never truncated; it is set smaller.

**The code is vector.** Every dark module is a filled rectangle in PDF user
space, so the same file prints correctly on an A4 flyer and on a two-metre
banner. A test fails if an `/XObject` or `/Subtype /Image` ever appears — a
rasterised QR blown up for signage is how a code that scanned on the designer's
screen fails on the wall.

⛔⛔ **The white plate is the quiet zone, and it is measured in MODULES.** It was
a percentage inset, which is generous on a version 2 symbol and **3.2 modules on
a version 6 one** — under the spec's minimum of four, on the poster it was made
for. The tests now measure the drawn geometry against the builder's own reported
plate, on all four sides, at every version a real destination reaches. ⛔ Never
crop the plate tighter, ⛔ never tint it, and ⛔ never invert the code to suit the
black ground: out of spec, and a good share of phone cameras refuse it.

Text is WinAnsi (single-byte). Curly quotes, dashes and ellipses are folded to
what the face can draw, so `What's On` keeps its apostrophe.

⚠ **Not carried over from the reference:** the speckled grain on the letterforms.
That is a raster texture and this is a vector page; adding it would mean
embedding an image and losing the reason the poster is vector in the first
place.

## 8 · ⛔ NOT verified — open items

1. **The migration has not been applied.** `20260821000004_qr1_qr_codes.sql` is
   authored, not run. Until it is, SAVE TO MY QR CODES fails and MY QR CODES is
   empty. Everything else — preview, PDF, PNG, copy link, every `/q/` route —
   works without it. The file carries its own VERIFY block, including the
   forged-attribution probe.
2. **No signed-in save has ever happened.** The RLS policies are written against
   `can_act_as()` and have not been exercised by a real client write. Do the
   forgery probe in the migration's VERIFY block before trusting them.
3. **Nothing has been scanned off paper.** The code has been read back out of a
   300 dpi render of the finished PDF with zero errors, which is as close as a
   machine gets; what it cannot test is ink, paper and a camera. Print one A4
   and one A5, scan both with a cheap phone in bad light. This is the acceptance
   test the parity gap in §5 leaves open.
4. **The printed address contains a `#`.** `https://yespleez.com/#/q/event/{id}`
   works with every scanner tested, and it needs no infrastructure. The
   alternative — a Cloudflare Pages `_redirects` mapping `/q/:type/:id` to the
   hash form, so the printed URL has no fragment — is more compatible with old
   scanners and link previews, **but it makes every printed code depend on a
   redirect being deployed and never removed.** That is a worse failure mode for
   paper than the one it fixes. Owner's call; if it is taken, both forms must be
   served forever.
5. **`ShareSheet` is still not mounted anywhere.** The QR row was added to it and
   the screens declare `qr: {type, id}` on their share targets, so it works the
   moment the sheet is rendered again — but the header's share icon was removed
   on 2026-08-04 and nothing renders `<ShareSheet>` today. **It is ready, not
   shipped.** The live entry points are the dashboard section and PROMOTE in an
   event's manage menu.
6. **No scan analytics.** The seam is `?s={qr_code_id}` on the destination URL,
   documented in `qrDestinations.js`, additive, and written by nothing. Turning
   it on is a new table plus a privacy answer that satisfies the analytics
   ruling on masked event ids — not a column on `qr_codes`.
