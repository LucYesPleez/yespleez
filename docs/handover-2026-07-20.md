## 6 · Two principles, both earned the hard way

### `12.1` — a recall-oriented engine must not gate a precision-oriented decision

`duplicate-detection.js` asks *"could these be the same entity?"* and is tuned for
recall because a reviewer confirms everything. Owner resolution asks *"can I assign
unattended?"* and must be precision-tuned because nothing downstream catches a wrong
answer. Measured: the matcher scores `"Thick Ear"` vs `"Thick Ear Records"` at **100%**.
Re-derive the threshold for the decision; never inherit the engine's.

### `13.1` — unit tests validate implementations, integration tests validate contracts

**Every new consumer of a subsystem needs at least one test on the PRODUCTION CALL
PATH.** Phase 16 produced six defects of identical shape: a module existed, behaved
correctly, its tests passed, and the caller never satisfied the contract. A unit test
cannot catch an argument that is never passed or a script tag never added.

## 7 · How to verify in this codebase — read this before reporting anything done

The single most repeated failure this session was **"build passes + lint passes,
therefore it works."** In this codebase that is worth very little:

- `vite build` does **not** error on undefined identifiers. A deleted state setter left
  behind is a runtime `ReferenceError` that builds clean and ships.
- Neither build nor lint can see a **database CHECK constraint**. Follows were rejected
  for hours with `23514` while every static check passed.
- A **green test suite proves nothing about the caller.** See `13.1`.
- **Anon REST reads return `[]` under RLS.** Empty is not proof of empty — several
  "0 rows" claims this session were policy artifacts, not data. Read as the
  authenticated user or via the SQL editor.

What actually worked, every time: **run the app and do the thing.**

**The browser preview pane is signed in as the owner's account** (`lucious.aus@gmail.com`),
so authenticated paths — follow, dashboards, profile actions — *can* be driven and
verified directly. A whole afternoon was lost to assuming otherwise. Check before
claiming a limitation.

Studio has no browser session requirement: `npm test` (94 tests, `node:test`) plus
driving `localhost:4000`.
